## Fixed

- StoreKit transactions are finished only after the backend accepts their signed receipt and updates the entitlement store. Network, server and ownership failures preserve unfinished transactions for retry. Sign-in/foreground reconciliation replays unfinished transactions; restore also waits for server acknowledgement. A historical receipt whose purchase attempt was lost during the authorized fresh-database migration falls back to verified restore only for `NOT_FOUND` naming `PurchaseAttempt`. Product-not-found and ownership errors never enter this recovery path.
- Purchase acknowledgement failures have a recovery message with Restore. A successful StoreKit sheet alone does not dismiss the paywall or grant local paid access. Existing subscriptions use the token returned by StoreKit rather than assuming the newest purchase-attempt UUID must match.
- Trial eligibility comes from the live StoreKit subscription group. Selected-product CTA text, trial wording and annual savings use actual eligibility and StoreKit prices. Removed unsupported unlimited/placeholder paid-usage claims.
- Added the backend's current paywall placements and canonical project/estimate usage metric codes. Paid usage displays the server's finite caps; absent buckets no longer create unlimited access or five synthetic starter credits. Monthly/daily/weekly usage denials display a limit notice. Terminal subscription states and billing retry without valid grace do not grant paid features.
- Local estimate PDF export prepares the file locally, then requires the server's atomic quote-export approval before returning it for upload or sharing. Required reads and local rendering failures do not consume quota; a server denial removes the prepared temporary file and propagates the error. Required estimate and line-item reads propagate failures; an unavailable line-item response can no longer produce a misleading zero-dollar PDF. Empty estimates show guidance before consuming quota. Saved-PDF downloads reject unsuccessful HTTP responses and bytes without a PDF header.
- Signup validation mirrors current server name, email and bcrypt password constraints, including the 72-byte UTF-8 limit. Form actions reject duplicate submission while loading. Signup explains password/name requirements; password recovery scrolls and supports a larger sheet when the keyboard or text size needs space.
- Apple and Google requests now carry independent random nonce proofs. Apple sends and checks state, retains its authorization controller and anchors to the active window. Google retains its authorization-code/S256 PKCE and state checks, adds the signed nonce proof and handles failure to start its system authentication session. Secure-random generation failures abort the attempt. Backend nonce verification was implemented separately by the backend agent; old clients without a nonce remain compatible.
- The decorative dashboard hero is capped at 260 points on regular-width layouts. Actual before/after iPad landscape captures verify that the business summary and primary action remain visible. Phones retain the original aspect ratio.
- Search clear controls have a named 44-point target. The image comparison supports VoiceOver adjustment, avoids per-drag spring animation and downsamples supplied image data off the main actor. Repeating decorative animations and videos respect Reduce Motion; videos stop while the scene is inactive.

## Remaining findings and focused follow-up

1. **Tablet content composition — runtime observed.** The hero issue is fixed, but project detail still stretches metadata across the full landscape width while the comparison remains a narrow centered image. The full-screen comparison crops the kitchen into a tall central viewport with substantial side space. Follow up with responsive summary/preview columns and an image aspect that uses the available tablet space. Verify portrait, landscape, split-screen and large text sizes; the current walkthrough establishes only the captured landscape layout.
2. **Apple credential-revocation lifecycle — source confirmed.** The client does not persist Apple's stable user identifier, call `getCredentialState` on session restoration or observe Apple credential-revocation notifications. The server does not yet complete Apple's authorization-code/refresh-token revocation lifecycle. Coordinate a provider-aware session design and test revocation/account deletion across client and server before claiming that lifecycle is complete.
3. **PDF work on the main actor — source-only performance candidate.** `Features/Projects/Detail/Views/ProjectDetailView.swift` explicitly renders the complete PDF on `MainActor`; large estimates with photos may block interaction. Profile a representative long estimate first, then move safe preparation/encoding off the main actor and preserve UIKit drawing requirements. No measured hitch duration is claimed.
4. **Swift 6 migration — compiler evidence.** Existing isolation warnings cover image-transfer closures, model decoding, notifications and UIKit delegates. Resolve by ownership boundary rather than suppressing diagnostics before enabling strict Swift 6 language mode. This audit did not undertake that broad migration.
